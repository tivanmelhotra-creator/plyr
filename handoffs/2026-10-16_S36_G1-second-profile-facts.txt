S36 — owner brief 2 / G.1: a second profile of the SAME branch (user-data-dir) by hand while the first runs under Playwright.
Linux sandbox, Xvfb :77 + openbox, Playwright's pinned Chromium (chromium.executablePath()). Docker: NOT RUN (owner: do not install Docker here).
Scripts: tools/s36/second-profile-facts.mjs, which-switch.mjs, forward-under-playwright.mjs, forward-consequences.mjs, identify-profile-targets.mjs

ANSWER: exit code 21 is NOT a Chromium limit. It is caused by Playwright's default switch --enable-automation on the FIRST browser.
  - First under plain Playwright (with --enable-automation) -> plain 2nd launch: exit 21 "Failed to create ... SingletonLock: File exists"
    (Chromium refuses to forward into a browser started for automation).
  - SingletonLock is NOT a hostname/PID-namespace artifact: lock -> "<our hostname>-<pid>", hostname matches, pid alive in our namespace, SingletonSocket present.
  - Same first browser started WITHOUT --enable-automation (all other Playwright switches kept, incl. --remote-debugging-pipe):
    plain 2nd launch: exit 0, forwarded into the SAME process, a window for profile-002 opens, folder profile-002 created.
  - The app ALREADY launches Browser-Profiles browsers without it (core/BrowserProfile IGNORED_DEFAULT_ARGS = --disable-extensions, --enable-automation),
    so in the app a second profile CAN be opened by hand in the same branch.
Consequences (measured, first launched exactly as the app does):
  a) Playwright's context SEES the second profile's tabs (context.pages() and the 'page' event include them) -> automation must ignore them.
  b) Profiles stay separate: a cookie set in profile-001 is not visible in profile-002.
  c) Closing the Playwright context (Stop of the first browser, run end) closes BOTH windows (one process).
  d) Closing the second profile's window leaves the first Playwright session working.
  e) Every tab carries its profile's CDP browserContextId (also tabs opened later with Ctrl+T), so the server can tell them apart.
=> G.2 applies (hold-to-confirm, manual-only second browser).
